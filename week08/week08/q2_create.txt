=== 任務 3：自己建立第二張表 crew ===
請自行寫出 CREATE TABLE 語句，建立 crew 表，需包含以下欄位：
- id：整數，自動遞增，主鍵
- name：字串，最多 50 字元，不允許空值
- rank：字串，最多 30 字元（職位：Captain / Officer / Engineer / Crew）
- ship_id：整數（對應 ships 表的 id）
- salary：小數（DECIMAL(10,2)）

（貼上你寫的 CREATE TABLE 語句）
CREATE TABLE crew (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    `rank` VARCHAR(30),
    ship_id INT,
    salary DECIMAL(10,2)

請回答：
Q：為什麼 crew 表的 ship_id 要對應 ships 表的 id？這樣設計有什麼好處？
A：
因為在現實世界中，一位船員（crew）通常會隸屬於某特定一艘船（ship），這在資料庫中屬於「一對多（One-to-Many）」的關係（一艘船可以有多名船員）。
讓 crew 表的 ship_id 對應 ships 表的 id（此設計稱為外鍵/Foreign Key 概念）有以下好處：
1. 資料完整性與準確性：可以確保每位船員關聯到的都是真正存在於 ships 表中的船隻，避免出現找不到船的「孤兒數據」。
2. 節省儲存空間（減少資料重複）：crew 表只需要儲存一個簡單的整數（ship_id），不需要重複記錄該船隻的名稱、類型、噸位等詳細資訊，當船隻資料需要修改時，也只需更改 ships 表一處即可。
3. 方便進行關聯查詢（JOIN）：未來可以使用 SQL 的 JOIN 指令，輕鬆查詢出「某艘船上有哪些船員」或「某位船員正在哪艘船上服役」。
