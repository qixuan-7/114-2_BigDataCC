=== 任務 6：觀念回答 ===
Q1：為什麼不要直接在 base 環境安裝專案套件？這樣做有什麼壞處？
A1：base 環境是 Conda 的預設核心環境。如果所有專案都直接安裝在 base 中，不同專案所需的套件版本可能會互相衝突（例如 A 專案需要舊版套件，B 專案需要新版），導致原本可執行的程式壞掉。此外，這也會使 base 環境變得臃腫，一旦損壞，可能需要重新安裝整個 Anaconda/Miniconda。

Q2：conda install 和 pip install 有什麼差異？什麼情況下會建議用 pip？
A2：
1. 差異：conda 不僅管理 Python 套件，還能管理二進位依賴項（如 C/C++ 庫、不同版本的 Python 本身），並會嚴格檢查所有套件的相依性；而 pip 是 Python 官方的套件管理器，主要專注於 Python 模組的安裝，相依性檢查較寬鬆。
2. 建議使用 pip 的時機：當某個特定的 Python 套件在 Conda 的官方或第三方頻道（如 conda-forge）找不到，但可以在 PyPI（pip 的資料庫）上找到時，就會建議在已啟動的 conda 環境中使用 pip install 安裝。

Q3：environment.yml 的用途是什麼？換電腦時要怎麼用它快速重建環境？
A3：
1. 用途：記錄當前 Conda 環境的所有資訊，包含環境名稱、安裝頻道（channels）以及所有套件的精確版本，用於專案環境的備份與團隊共享。
2. 重建方法：換電腦時，只需將該檔案複製到新電腦，在終端機切換到該檔案所在目錄，並執行指令：`conda env create -f environment.yml`，Conda 就會自動讀取檔案並完整還原出一模一樣的開發環境。
